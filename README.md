# MiniRAG на Python

Учебный проект по лабораторной работе 20 «Сборка MiniRAG на Python». Программа ищет факты в текстовом файле и использует найденные фрагменты для ответа на вопрос пользователя.

**Текущий статус:** репозиторий подготовлен для реализации. Этот README описывает проект по заданию; команды запуска будут работать после создания соответствующих файлов. В PDF корневая папка называется `Lesson_20`, в этом репозитории — `mini_RAG`.

## Цель

Собрать цепочку Retrieval-Augmented Generation (RAG): чтение источника, очистка текста, разбиение на чанки, получение векторов, сохранение индекса, поиск, подготовка промпта и генерация ответа через Gemini.

Предусмотрены два режима:

- `demo` — вывод первого найденного фрагмента с пометкой `[ДЕМО без генерации]`. Gemini не вызывается.
- `gemini` — передача вопроса и найденного контекста в Gemini API для формирования ответа.

Если список найденных фрагментов пуст, обработчик возвращает `В базе нет ответа.` без обращения к API. Непустой список сам по себе не гарантирует наличия ответа: похожий текст может не содержать нужного факта.

## Как работает проект

Индексирование запускается отдельно:

```text
source/source.txt → чтение → очистка → чанки → векторы → database/database.txt
```

Обработка вопроса использует сохраненный индекс:

```text
Вопрос → вектор вопроса → поиск top_k фрагментов → контекст → промпт → ответ
```

Для источника и вопросов используется одна модель `paraphrase-multilingual-MiniLM-L12-v2`. Она работает на CPU и создает векторы из 384 чисел. Поиск сравнивает векторы по косинусному сходству.

Исходный текст хранится рядом с вектором. В контекст включаются пронумерованные тексты найденных фрагментов без оценок сходства.

## Требования

- Python 3.11 или 3.12.
- macOS, Linux или Windows.
- Интернет для установки зависимостей и первой загрузки модели embeddings.
- Собственный ключ и доступ к Gemini API для режима `gemini`.

Содержимое будущего `requirements.txt` по заданию:

```text
sentence-transformers
numpy
scikit-learn
google-genai
```

## Подготовка окружения

Все команды выполняются из корня `mini_RAG`. Сначала создайте `requirements.txt` с приведенным выше списком библиотек.

### macOS и Linux

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install --upgrade pip
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pip check
```

При использовании Python 3.11 замените `python3.12` на `python3.11`. Если рабочее окружение уже создано в PyCharm, первую команду пропустите.

### Windows PowerShell

```powershell
py -3.12 -m venv .venv
& .\.venv\Scripts\python.exe -m pip install --upgrade pip
& .\.venv\Scripts\python.exe -m pip install -r requirements.txt
& .\.venv\Scripts\python.exe -m pip check
```

Для Python 3.11 замените `-3.12` на `-3.11`. В Windows CMD используйте те же пути без начального `&`.

Ожидаемый результат проверки зависимостей: `No broken requirements found.` Файлы проекта сохраняйте в UTF-8.

## Источник фактов

Создайте `source/source.txt` с четырьмя строками:

```text
Заказы отправляются %#$ по предоплате.
Доставка %#$ занимает 3-5 дней.
В нашем магазине %#$ предусмотрен возврат.
Адрес нашего %#$ магазина - город Берлин.
```

Символы `%#$` оставлены намеренно для проверки очистки. После подготовки должны получиться четыре непустых чанка. Учебный фильтр рассчитан на русскую базу и удаляет латинские буквы.

## Индексирование и запуск

После реализации модулей создайте индекс:

```bash
.venv/bin/python -m rag.ingestion.ingestion
```

Ожидаемый вывод: `Сохранено фрагментов: 4`. Файл `database/database.txt` должен содержать четыре записи.

Запустите demo:

```bash
export RAG_MODE="demo"
.venv/bin/python main.py
```

Дождитесь приглашения `Вопрос:`, введите вопрос и нажмите Enter. После ответа программа завершится.

Для PowerShell:

```powershell
& .\.venv\Scripts\python.exe -m rag.ingestion.ingestion
$env:RAG_MODE="demo"
& .\.venv\Scripts\python.exe main.py
```

### Gemini

Ключ передается через переменную окружения `GEMINI_API_KEY`. Задайте его в том же терминале, из которого запускаете Python. Значение ниже — заглушка для замены собственным ключом.

```bash
export GEMINI_API_KEY="YOUR_API_KEY"
.venv/bin/python -m examples.e20_07_gemini
export RAG_MODE="gemini"
.venv/bin/python main.py
```

PowerShell:

```powershell
$env:GEMINI_API_KEY="YOUR_API_KEY"
& .\.venv\Scripts\python.exe -m examples.e20_07_gemini
$env:RAG_MODE="gemini"
& .\.venv\Scripts\python.exe main.py
```

`GEMINI_MODEL` позволяет задать имя модели, доступной вашему аккаунту. Наличие ключа не подтверждает успешный запрос: доступ и квоты проверяются отдельно. Если API недоступен, продолжайте в demo и укажите в отчете «Gemini не проверен» с причиной.

Ключ не включайте в код, README, отчет или коммиты. Создание `.env` само по себе не передает настройки программе: в лабораторной используется `os.getenv` и окружение процесса.

## Проверка результата

| Вопрос | Корректный смысл ответа по источнику |
| --- | --- |
| Можно ли оплатить заказ после получения? | Заказы отправляются по предоплате |
| Сколько ждать доставку? | 3–5 дней |
| Где находится магазин? | Берлин |
| Сколько стоит доставка? | В источнике нет цены |
| За сколько дней возможен возврат? | Возврат предусмотрен, но срок не указан |

Demo возвращает первый найденный текст даже тогда, когда он не отвечает на вопрос. Проверку отказа выдумывать отсутствующие сведения при генерации выполняйте отдельно в Gemini и сверяйте ответ с фактическим промптом.

Контрольные примеры для macOS/Linux:

```bash

.venv/bin/python -m examples.e20_09_vectors
.venv/bin/python -m examples.e20_08_numbers
.venv/bin/python -m examples.e20_03_search
.venv/bin/python -m examples.e20_04_context
.venv/bin/python -m examples.e20_05_prompt
```

## Обновление базы

После изменения `source/source.txt` снова выполните индексирование. До этого поиск продолжает использовать старый `database/database.txt`. После смены модели embeddings индекс также нужно перестроить.

Для опыта этапа 17 временно замените первый факт на `Заказ можно оплатить после получения.` и сравните поиск до и после индексирования. В конце восстановите исходные четыре строки и снова создайте индекс. Обновление индекса не является обучением Gemini.

## Самостоятельные задания

- `task01.py`: собрать контекст из двух фрагментов и проверить пустой список.
- `task02.py`: собрать промпт и проверить наличие вопроса и слова «Берлин».
- `task03.py`: сравнить demo с непустым и пустым списком фрагментов.
- `task04.py`: выполнить векторизацию вопроса о доставке, поиск с `top_k=2` и вывод в demo.
- `task05.py`: собрать промпт с вопросом о цене, имея только факт о сроке доставки.

Запуск каждого решения: `.venv/bin/python -m practice.task01` с заменой имени модуля на нужное.
